== v2.0 Strictness Recap

[cols="1,3,4"]
|===
| Grade | Release Stage | Hard Requirement (v2.0)

| X | None             | Untested.
| F | Reject           | Harmful, wasteful, or superseded.
| E | Pre-alpha        | >=1 test, failures documented.
| D | Alpha            | Test matrix + scope documented + *RSR compliance mandatory*.
| C | Alpha-stable     | Dogfooded, CI green, *deep per-file + per-directory annotation*.
| B | Beta             | 6+ *diverse* external targets, issues fed back.
| A | Stable           | Real-world external feedback confirms value; no harm.
|===

Publication requires B+. Long alpha is discipline, not shame.

== Verdict

*Current CRG grade: **D (Alpha, with structural-policy debt)**.*

Self-declared grade: *B*. Audited grade: *D*. **This is an overclaim of two
grades**, demonstrating exactly the v2.0 "embarrassing overclaimed
releases" failure mode the standard was written to prevent.

Recommended action (per v2.0 "demote immediately"): update
`.machine_readable/6a2/STATE.a2ml` to `crg-grade = "D"` with a
`crg-grade-notes` entry citing this audit, and remove the "CRG B blitz"
label from `testing-phase`.

The D grade is earned on three positive signals:

1. 21 RSR workflows present — the CI scaffolding is real.
2. ~230 tests passing across cli + core + shared crates.
3. Contractile trident present + `.machine_readable/6a2/` canonical A2ML.

What blocks *immediate* promotion to C:

1. `[dogfooding-status]` section missing. Populate with concrete "done —
   <evidence>" entries tying the suite to real academic workflow use.
2. `docs/practice/DOGFOOD-LOG.adoc` absent. Start it, date-stamped.
3. Per-directory orientation READMEs missing for `cli/`, `components/`,
   and each of `components/{ai-jail,backend,core,office-addin,shared}/`.
4. `docs/architecture/` + `docs/decisions/` subtrees absent. ADRs exist
   only as scattered design docs (`MOODLE_OAUTH_DESIGN.adoc`,
   `PROVEN_INTEGRATION.adoc`) — consolidate into numbered ADRs.
5. Run the pending backend test suite (`mix test` in a BEAM-enabled env).
6. Run the office-addin ReScript test suite and record PASS count.
7. Provide a CUDA-optional fallback / stub for the AI-jail tests so
   `ai-jail = BLOCKED` doesn't permanently bottleneck the test matrix.
8. Fix the structural-policy debts: rename `Containerfiles/Dockerfile.*`
   to `Containerfiles/Containerfile.*`; migrate office-addin away from
   `package.json`/`webpack`; add `guix.scm`; add root `docs/READINESS.md`
   populated from `rsr-template-repo/READINESS.md`.

What blocks promotion to B (even after C is met):

1. *No* external targets recorded — needs 6+ diverse ones.
2. *No* external contributor flow, *no* closed-issue trail with
   external-reporter labels, *no* feedback-fed-back log.
3. `completion-percentage = 42` is incompatible with B under any honest
   reading. The suite needs broad completion before it can credibly be
   tested broadly.

== Notes on Non-Negotiables Respected by this Audit

- This audit does *not* attempt to force a v2.0 C claim by mass-generating
  READMEs. Per v2.0 Principle 3, a grade is earned by evidence the suite
  actually has today.
- AI-jail's CUDA dependency is respected as a real environmental blocker,
  not filed as proof debt.
- No changes were made to the repo during the audit itself; the audit is a
  read-only inspection. Remediation (STATE.a2ml demotion, structural fixes)
  is a separate action the author chooses to take.
