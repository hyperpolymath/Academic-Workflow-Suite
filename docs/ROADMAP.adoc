= Academic Workflow Suite Roadmap
:toc: auto
:toclevels: 3

== Overview

This document outlines potential development directions for Academic Workflow Suite. Each direction represents a strategic path that could be pursued based on user needs, resource availability, and ecosystem evolution.

== Current State (v0.1.0)

=== Foundation Complete

* Core engine skeleton with event sourcing (Rust/LMDB)
* AI Jail skeleton with Candle ML (Rust)
* Office Add-in skeleton (ReScript/Office.js)
* SHA3-512 anonymization framework
* Basic project structure and infrastructure
* Container configuration templates
* Contractiles build system (just/Mustfile/Dustfile)

=== In Progress (v0.2.0 Target)

* Core Engine REST API implementation (Actix-Web)
* AI Jail inference implementation (llama.cpp/Ollama)
* Office Add-in UI development (React/ReScript)
* End-to-end workflow integration
* Testing and documentation

== Direction 1: Deep Privacy Enhancement

_Focus: Making AWS the gold standard for privacy-preserving educational AI_

=== Phase 1: Cryptographic Hardening (v0.3.0)

* [ ] Integrate `proven` SafeCrypto for verified SHA3/AES
* [ ] Add homomorphic encryption for AI queries (SEAL/OpenFHE)
* [ ] Implement secure multi-party computation for collaborative marking
* [ ] Zero-knowledge proofs for audit compliance without data exposure

=== Phase 2: Differential Privacy (v0.4.0)

* [ ] Add noise injection for aggregate statistics
* [ ] Privacy budget tracking per student
* [ ] Federated learning support (model stays local, only gradients shared)
* [ ] Formal privacy guarantees with ε-differential privacy

=== Phase 3: Trustless Architecture (v0.5.0)

* [ ] TEE support (Intel SGX, ARM TrustZone) for AI inference
* [ ] Verifiable computation proofs for AI outputs
* [ ] Decentralized audit trail (append-only Merkle tree)
* [ ] Hardware attestation for AI jail integrity

=== Potential Outcomes

* University-wide deployment with provable GDPR compliance
* Research publications on privacy-preserving educational AI
* Adoption by privacy-conscious institutions globally

== Technology Investment Areas

=== Proven Library Integration

[cols="1,2,1"]
|===
| Module | Application | Priority

| SafeCrypto | Student ID hashing, encryption | HIGH
| SafeJson | AI Jail IPC, API parsing | HIGH
| SafeRegex | PII detection | MEDIUM
| SafeStateMachine | Event sourcing | MEDIUM
| SafeAudit | Compliance logging | LOW
|===

=== Container & Runtime

* **Primary**: nerdctl + containerd (rootless)
* **Fallback**: podman (rootless)
* **Isolation**: gVisor/Firecracker for AI jail
* **Orchestration**: None (single-machine focus)

=== Build & Package

* **Build**: just (contractiles pattern)
* **Package**: Guix primary, Nix fallback
* **JS Runtime**: Deno (no npm in production)
* **Containers**: OCI-compliant images

== Decision Framework

When choosing directions, consider:

[cols="1,3"]
|===
| Factor | Questions

| *User Impact*
| How many tutors benefit? How much time saved?

| *Privacy Alignment*
| Does this strengthen or weaken privacy guarantees?

| *Technical Debt*
| Does this add complexity? Is it maintainable?

| *Community*
| Can contributors help? Is there external interest?

| *Sustainability*
| Does this enable funding? Reduce costs?
|===

== Recommended Priority

Based on current project state and user needs:

1. **Direction 1** (Privacy) - Core differentiator, proven integration
2. **Direction 2** (LMS) - Highest user-requested feature
3. **Direction 3** (AI Models) - Flexibility and future-proofing
4. **Direction 4** (Collaborative) - Team marking is common
5. **Direction 6** (Mobile) - Quality of life improvement
6. **Direction 5** (Student) - Scope expansion, later phase
7. **Direction 7** (Research) - Requires user base first
8. **Direction 8** (Enterprise) - When demand justifies
