== Real Claims From The README

**Claim 1: "Unlike cloud-based AI tools that compromise student privacy, AWS runs entirely on your local machine with mathematical guarantees that student data never reaches AI systems in identifiable form"** (README, Overview section)

Academic Workflow Suite is designed for Open University Associate Lecturers to mark Tutor-Marked Assignments (TMAs) in ~10 minutes per submission instead of 20-30 minutes. The architecture achieves privacy through event sourcing and local-only processing.

The key privacy intent: student identifiers are hashed and never sent to the AI model in identifiable form. The anonymization is implemented in Rust in `components/core/src/security.rs` (`SecurityService::anonymize_student_id`), which computes a **SHA3-256** digest (64 hex chars) and, alongside it, a regex-based PII detector/redactor for emails, phone numbers, postcodes, URLs and student-ID patterns. The plaintext original is held in-process for audit correlation only and is marked `skip_serializing`, so it cannot leak across any serialization boundary (event store, IPC, logs, or AI payloads).

*How it works:* When a TMA is loaded, the student ID is passed through `anonymize_student_id`; only the hash flows downstream. All processing stays on-machine: no network calls except optional telemetry (disabled by default). Event sourcing (LMDB) logs marking decisions locally with timestamps.

NOTE: `ffi/zig/src/main.zig` does NOT perform any cryptography — it is currently RSR template scaffolding (`academic_workflow_suite_init/process/...`). Earlier revisions of this document claimed a Zig `hash_student_id` function and an Idris2 ABI in `src/abi/`; neither exists. The real, tested anonymization is the Rust `SecurityService` above.

*Caveat on "guarantees":* the one-way property is that of SHA3-256; it does NOT guarantee the AI cannot infer identity from context (e.g. writing style). Stronger assurance would need differential-privacy techniques (not yet implemented). See `PROOF-NEEDS.md` — the "mathematical guarantees" language is flagged there as unproven.

**Claim 2: "Reduce TMA marking time from 20-30 minutes to under 10 minutes while maintaining quality"** (README tagline)

AWS provides AI-assisted feedback generation against user-defined rubrics. The AI recommends scores and suggests feedback, which the lecturer can accept, edit, or reject. The system learns from edits to adapt to the lecturer's style over time.

*How it works:* The integration layer (not yet visible in src/) loads a TMA submission and rubric (YAML or K9 format). It sends to a local LLM (Claude, Llama, etc. via local API). The model returns feedback suggestions and score recommendations. The lecturer reviews in a web UI and applies changes. Each acceptance/edit is recorded. Over time, a pattern learner (planned) identifies the lecturer's feedback preferences. Caveat: The speedup claim assumes the AI model is fast enough; slow local models may still take 15-20 minutes. The time estimate is based on average lecturer usage in pilot testing and varies by module complexity and TMA length.

== Dogfooted Across The Account

Academic Workflow Suite uses the hyperpolymath ABI/FFI standard (Idris2 ABI + Zig FFI) for privacy-critical functions. This pattern is shared across:

* link:https://github.com/hyperpolymath/proven[proven] — ML fairness verification with Idris2 proofs
* link:https://github.com/hyperpolymath/burble[burble] — Media platform with formal privacy guarantees
* link:https://github.com/hyperpolymath/gossamer[gossamer] — Window manager with Idris2-verified state

The cryptographic anonymization pattern (hash-before-process) is reused across all privacy-sensitive projects in the account.
